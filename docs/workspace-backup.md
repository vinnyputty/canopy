# Workspace backup and transfer

Use **Settings → Workspace backup and transfer** before upgrading or moving machines. **Review export metadata** shows the exact JSON before **Export reviewed backup…** opens the save chooser. Export captures the reviewed state; review again to capture later changes. Canceled choosers leave the workspace untouched. Export outside Canopy's user-data directory.

The JSON contains server URLs and names, connection IDs, root keys and summaries, favorites, recent/closed roots, saved view names, root scopes and filters, root/connection table settings, appearance, reading, pane sizes, and literal keyboard shortcuts. Export normalizes navigation history: open roots take precedence over matching closed entries, the newest closed entry is retained per root, and colliding closed-tab IDs receive a `closed-` prefix. These metadata can reveal private project names, issue titles, workflow details, and identifiers in filters. Treat backups as private files. They are not encrypted; do not commit or publish them.

**Credentials and tokens never participate.** Connection descriptors contain only `id`, `name`, `provider`, and `url`. Account names and repository access lists are excluded. URLs must omit user information, query strings, and fragments. Issue snapshots, comments, descriptions, seen baselines, expansion, selection, focus, and scroll history are excluded. Sensitive cache transfer has no opt-in. Only `workspace.json` changes during import; credentials, provider caches, window state, and other user data remain intact. Existing seen baselines remain local even in Replace mode.

## Import and recovery

Choose a backup, then explicitly map each source connection to an existing destination. Matching IDs alone are insufficient. The provider and server URL must match, and each source needs a distinct destination. Check the displayed account and repository access. A backup cannot authenticate you or create connections. On a new machine, close the dialog, reconnect through Connection setup, then select the backup again. Disconnected source references block export until their connection is restored or their roots/views are removed.

**Merge** adds non-conflicting roots, favorites, recent/closed roots, saved views, and table settings. Existing root identities, table settings, and saved view IDs or names win. Appearance, reading, shortcuts, and active selection stay local. Roots compare by connection and case-insensitive key; roots on separate connections remain distinct. Tab ID collisions receive an `import-` prefix. Exceeding a collection limit fails rather than dropping entries.

**Replace** uses the backup's roots, favorites, saved views, appearance, reading, shortcuts, and active selection. It removes the previous portable setup. Both modes show the resulting counts, conflicts/removals, and exact resulting workspace before Apply. Mapping or mode changes invalidate the preview. Workspace or connection changes after preview require a new preview. Connection approval is rechecked inside the queued import transaction and immediately before every replacement attempt, including after staging and Windows lock retries. Imported roots fetch data under the explicitly mapped destination account.

Apply validates first and stages one private workspace file, then atomically replaces `workspace.json`. A staging or replacement failure preserves the prior file. A failed import does not need a compensating write. Applying reloads the renderer to discard stale issue displays. **Undo last import**, in the same dialog, restores the previous workspace atomically while the imported workspace is unchanged; later workspace changes (including refreshes that update seen baselines) block undo to avoid erasing new work. Undo survives renderer reloads, but not application exit. Keep a separate export for recovery after subsequent edits.

## Version 1 format and compatibility

The envelope is `{ "format": "canopy-workspace", "version": 1, "createdAt": "2026-10-02T00:00:00.000Z", "connections": [...], "workspace": {...} }`. `createdAt` uses UTC ISO milliseconds and must round-trip to the same valid calendar date. This is a setup backup, not an arbitrary copy of the user-data directory or a raw legacy `workspace.json` import.

`connections` is an array of referenced connection descriptors. Supported providers are `jira`, `github`, and the local `demo`. HTTPS URLs are normalized without a trailing slash; demo uses `Local sample workspace`. No unreferenced connection metadata is exported.

`workspace` requires `tabs`, `activeTabId`, `shortcuts`, `theme`, and `sidebarCollapsed`. Its optional fields are `palette`, `reading`, `sidebarWidth`, `previewWidth`, `pinnedRoots`, `recentRoots`, `closedTabs`, `viewDefaults`, `rootViews`, `savedViews`, and `activeSavedViewId`. All nested fields follow Canopy's existing workspace types, with portable tabs restricted to `id`, `connectionId`, `rootKey`, optional `summary`, `filters`, `view`, and required `hideDone`, `expanded: []`, `scrollTop: 0`. Root-view keys encode `[connectionId, uppercaseRootKey]` as JSON. Saved views contain `id`, `name`, `roots`, `connectionIds`, `filters`, and `sort`.

Import rejects unknown fields at every fixed shape, credential/cache fields, invalid types or enums, duplicate connection/tab/root identities, invalid references, unsafe object keys, and conflicting shortcuts. Inputs are regular UTF-8 JSON files capped at 4,000,000 bytes. Limits include 100 connections/open tabs/saved views, 20 closed tabs, 1,000 favorite/recent roots and entries per view map, and existing bounds for filters, columns, text, and pane sizes. No partial salvage occurs on import. Export also enforces the formatted file's byte limit.

When `rootViews` is absent, import migrates tab-level table settings before constructing and merging view maps; existing destination settings win merge conflicts, and Replace uses imported settings. Version 1 accepts absent optional reading settings and migrates them with the existing workspace reading migration. Missing known shortcut commands become unassigned; shortcut modifiers stay literal when transferring between operating systems, so review them in Keyboard shortcuts afterward. Existing unversioned on-disk workspaces retain their existing view/reading recovery behavior before export; backup import uses strict validation. Unsupported envelope versions are rejected before any write. Future versions require an explicit migration and fixtures; unknown fields are never silently interpreted.
