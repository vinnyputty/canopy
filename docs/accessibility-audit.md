## Native qualification gate

Use disposable sample data and record the reviewed commit, OS/build, Electron version, tool/version, accessibility backend, input method, path, expected behavior, observed behavior, screenshots or event traces, and spoken output. Mark each path pass/fail/pending with evidence. Enable or change user accessibility settings only under separately authorized native acceptance; this baseline authorization does not allow such changes.

- **macOS:** Accessibility Inspector plus VoiceOver. Inspect the native AX hierarchy, focus changes, names/roles/values, modal boundaries, and live announcements. In the baseline environment, a read-only `AXIsProcessTrusted()` probe returned false and only Command Line Tools were selected; native inspection and spoken output were not qualified. No trust request or VoiceOver toggle was made.
- **Windows:** Accessibility Insights for Windows plus Narrator (or an explicitly recorded representative screen reader). Inspect UI Automation structure/focus/live-region events and verify spoken output.
- **Linux:** Accerciser plus Orca on a recorded distribution/desktop session and AT-SPI backend. Inspect native focus/role/name/state/event behavior and verify spoken output.

For each OS exercise opening a sample root, sidebar/tab traversal, tree navigation, summary edit/cancel/save/failure/Undo, picker selection/dismissal, dialog open/close/destination changes, refresh success/failure/retry, partial results, offline recovery, no results, and large text/narrow layouts. Verify native reduced motion and large text separately from Chromium emulation and Canopy's Reading settings. Native qualification on all three desktops is an eventual draft gate, not substituted by the current Mac harness. Keep native acceptance pending while independent source and fixture work continues.

## Criteria and integration

Current primary references used for uncertain criteria:

- [W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/), especially contrast, resize text, reflow, keyboard, focus order/visibility, name/role/value, and status messages.
- [W3C status messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html): waiting/results/error status must be programmatically exposed; tune feedback with native user testing to avoid excessive announcements.
- [W3C resize text](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html) and [reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html): preserve content and controls at enlargement; two-dimensional tables have a reflow exception, while surrounding controls still need usable layout.
- [WAI modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/): contain dialog focus and return it to the invoking control or a logical destination.
- [HTML canvas color-space conversion](https://html.spec.whatwg.org/multipage/canvas.html#colour-spaces-and-colour-space-conversion) specifies the browser conversion used by the prepared color measurement.
- [Electron accessibility](https://www.electronjs.org/docs/latest/tutorial/accessibility), [Apple Accessibility Inspector](https://developer.apple.com/documentation/accessibility/inspecting-the-accessibility-of-screens), [Microsoft native accessibility testing](https://learn.microsoft.com/en-us/windows/win32/winauto/accessibility-testingtools), and [GNOME Orca](https://orca.gnome.org/).
