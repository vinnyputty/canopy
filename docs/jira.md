# Jira provider notes

Canopy uses Jira Cloud REST API v3 through an OAuth request function already scoped to `api.atlassian.com/ex/jira/{cloudId}`. Searches use the enhanced `POST /rest/api/3/search/jql` endpoint and follow every `nextPageToken`; Jira search is eventually consistent, so a just-completed edit can briefly lag in a subsequent tree refresh.

The issue tree follows Jira's `parent` field one level at a time. This supports every hierarchy level exposed by the site rather than assuming a fixed epic/story/subtask shape. Issue links are shown as nonrecursive references on the issue that contains them because links can form cycles and do not define ownership.

Sibling dragging and rank undo call Jira Software's `PUT /rest/agile/1.0/issue/rank`. Placement uses `rankBeforeIssue` or `rankAfterIssue` to restore the original neighbor. It requires the Jira Software rank scope and a Rank field; Canopy rejects moves between different parents and moves of the tab root. Sites without an available Rank field display children in stable issue-key order and report that fallback in the tree warnings. Jira can still reject a valid sibling move because of project permissions or rank configuration, including a partial failure reported with HTTP 207.

Rank handles require a successful Rank query and issue-specific Schedule Issues and Edit Issues grants from `POST /rest/api/3/permissions/check`, checked in batches of up to 1,000 issues. Missing grants hide the corresponding handles; failed capability checks hide handles and explain that availability is unknown. This follows Atlassian's [ranking requirements](https://support.atlassian.com/jira-software-cloud/docs/rank-an-issue/) and [bulk permission API](https://developer.atlassian.com/cloud/jira/platform/rest/v3/api-group-permissions/#api-rest-api-3-permissions-check-post). A project type alone does not determine rank support. Jira remains authoritative when a rank write is submitted.

Column sorting is local to each sibling group. Priority order is loaded lazily through a JQL query with one representative issue per priority and `ORDER BY priority DESC`, using the existing search scope. The order is cached for the connection and set of priorities for the current app session. A failed lookup keeps Jira order visible with an explicit retry action. Missing assignees and priorities sort last in both directions; ties use natural issue-key order. Sorting by another column disables rank dragging and keyboard ranking.

Table views are saved per connection and root, independently of tab lifetime. Connection defaults and root overrides include columns, widths, sort, filters, text size, and row spacing. Each customized root keeps a complete view until reset to its connection's current default.

Priority metadata, assignee search, and workflow transitions load independently, each with its own error and Retry action. Provider caches live for the connection’s app session and are discarded on disconnect or credential replacement. Concurrent matching requests share their results. Priority metadata is issue-specific; transitions are scoped to the issue and its observed status. Status changes invalidate that issue’s picker metadata, rejected selections invalidate the relevant field, and Retry and undo request fresh choices. Other edits preserve unrelated choices; there is no timed cache expiry.

The assignee picker immediately shows up to 100 recently seen identities for the connection, seeded from loaded issues and user results. These are suggestions, not shared assignment grants: selecting a person checks their account ID against the current issue before submitting. Search and scrolling to the end (or Load more people) fetch additional candidates. The [assignable-user API](https://developer.atlassian.com/cloud/jira/platform/rest/v3/api-group-user-search/#api-rest-api-3-user-assignable-search-get) filters within a requested candidate window; a short or empty result does not mean discovery is complete. Canopy advances windows of 100 through Jira’s first 1,000 users and explains that discovery may remain incomplete. The identity cache does not make an exhaustive directory available.

A transition whose screen requires extra fields is displayed but marked as requiring fields. Canopy checks fresh transition metadata before submitting and refuses transitions with unsupported required fields.

Jira omits issues the signed-in user cannot browse. Canopy can report an inaccessible root directly, but Jira does not reveal inaccessible descendants, so it cannot distinguish them from absent children.

The renderer applies supported edits optimistically across tabs sharing a connection. Field writes are serialized per issue, ranking per connection. Tree refreshes wait for active editors and pending writes on their connection. Responses reapply writes completed after the request began; closing a tab invalidates its outstanding responses. Failed writes remove only their own optimistic change.

Undo is session-local and checks freshly fetched issue values or sibling order before writing. Status undo requires a currently available transition back with no required fields. Rank undo requires fresh supported ranking permissions for the moving issue, including when another display sort is active. Unsupported inverses and changed remote state are reported and skipped; transient failures remain retryable. These checks are best-effort: Jira does not expose an atomic compare-and-set for these operations, and its search results can lag completed writes.

Space on a focused tree row opens a read-only preview with its description, the ten newest comments, and linked issue references. Preview data loads on demand; moving the tree selection updates an open preview, and closing it restores focus without changing tree scroll. Comment errors leave the description and links available and can be retried. Descriptions and comments render as safe text with paragraph/list structure and link URLs; attachments and rich media remain in Jira. Comment ordering and permissions follow the [Jira comments API](https://developer.atlassian.com/cloud/jira/platform/rest/v3/api-group-issue-comments/).

Relationship labels describe the selected issue's direction (for example, “blocks” or “is blocked by”). References can be previewed or opened as a separate tree and are never traversed as hierarchy children. Each row's context menu supports copying its key, title, or Jira link and opening Jira. Right-click, the row actions button, or Shift+F10 opens that menu.

The preview's resize handle supports dragging, Left/Right arrows, and Home/End. Its preferred width is saved across launches; the pane fits within the window. Escape closes a row menu before closing the preview. Preview visibility is temporary and resets on a tab change.
