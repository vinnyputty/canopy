# Workspace controls

## Settings and reading scope

Sidebar **Settings** exposes Updates, Reading, Appearance, keyboard shortcuts, and connection setup. [Update preferences](updates.md) persist independently of issue workspace state; notices default off. Reading changes apply immediately to all tabs, newly opened roots, reopened tabs, and saved-view results, and save with the workspace. **Reset reading to Medium / Compact** resets only text size and row spacing. Appearance reset previews System / Default until saved; shortcut reset restores the keyboard defaults. Manage existing connections in the sidebar.

Columns, widths, sort, filters, hide-done, and status-transition sharing remain root choices with connection defaults. Root reset, connection defaults, Back/Forward, and reopening tabs retain the current app-wide reading preference.

On upgrade, an existing valid global reading setting wins. Otherwise migration takes the active tab's effective root override, connection default, or legacy tab snapshot, in that order. If unavailable, it takes the first valid preference from open tabs in tab order, then closed tabs in most-recent-first order, then connection defaults and root overrides in sorted key order. With no valid preference it uses Medium / Compact. Migration removes reading values from open and closed snapshots, root overrides, and connection defaults; subsequent launches retain the selected global setting.

Use **Next tasks** in a root toolbar to see unfinished issues from the whole root alongside the tree. The list includes unfinished parent issues and shows each issue’s ancestry, priority, status, assignee, and blocker state. **Show in tree** expands the path and selects that issue. Choose sibling rank, Jira priority, status, assignment, or blocker state as the ordering criterion; confirmed blocked issues follow clear and unknown issues. **Assigned to me** narrows the list to your issues. The list updates after edits and tree refreshes. GitHub priority is unavailable. Use **Inspect blockers** to load read-only relationships for a task; GitHub blocker state stays unknown until inspected. Missing link data, unknown blocker statuses, and partial reads remain explicit. Known active blockers retain their blocked state when other relationship data is incomplete. The list contains issues returned by the current connection; tree warnings indicate when part of the hierarchy could not be loaded.

Drag a tab onto another tab to move it to that position. Keyboard users can focus a tab and press `Alt+Shift+Left` or `Alt+Shift+Right`. Tab order is saved with the workspace.

Right-click a tab, or press `Shift+F10` while it is focused, to close other tabs, close tabs to its right, pin its root, copy its Jira link, or open it in Jira. Middle-click closes a tab. Pins are sidebar favorites: closing their tabs retains the favorites, and favorites do not affect tab ordering or bulk close actions. The sidebar unpin button removes a favorite. Move favorite up/down buttons reorder pins and save their order across restarts; parked favorites keep their position. All sidebar controls use native buttons reachable with Tab and Shift+Tab, activated with Enter or Space. Root actions include their connection in the accessible name; the current tree or saved view is marked as current. Sidebar organization announcements identify the action and its Undo.

The sidebar separates **Active tabs**, **Pinned roots**, **Saved views**, and **Recent roots**, with counts of the entries currently shown. Root rows display provider and connection alongside the cached summary; saved views display their source connections. A root can appear in several sections, and roots with the same key on different connections stay independent.

**Park for this session** moves a root’s entries from Active tabs, Pinned roots, and Recent roots into **Parked roots**. Tabs stay open and remain accessible in the tab strip. Parking keeps root views, selection, tree scroll, saved-view sources and results, and favorites intact. **Restore to sidebar** returns the entries to their sections. Parking and the last twenty organization Undo actions last for the current window session and clear on restart. The sidebar explains this lifetime beside Parked roots. **Undo** reverses pinning, unpinning, favorite reordering, parking, or restoring; later selection, scroll, refreshed data, and saved-view edits remain intact. Disconnecting a connection clears organization Undo so it cannot restore removed connection data. Pinning, reordering, and section refresh retain sidebar scroll where the remaining content permits it; removed or disabled focused actions move focus to an available action for that root.

Press `⌘⇧T` on macOS or `Ctrl+Shift+T` elsewhere to reopen the most recently closed tab, including its selection, scroll position, done and assignee/status/priority filters, table columns and widths, sorting, subtree focus, hierarchy expansion, and linked-issue expansion. Find-in-tree text stays with an open tab during the session and clears when that tab closes; it is excluded from saved tab snapshots. The last twenty closed tabs survive restarts. Bulk close records tabs from right to left for reopening. If a root is already open, reopening restores the saved state into its existing tab.

The open-issue picker selects its first result automatically. Up/Down moves the highlight without leaving the input; after Up/Down, Enter opens the highlighted suggestion. On a Jira connection, Enter opens a typed issue key or browse URL directly. Search starts after two characters and a short pause, including key prefixes that may also be complete keys. An uppercase project-key prefix such as `CAN` finds issue keys beginning with that text; lowercase words continue through summary search. Exact and prefix key matches lead summary matches; project context comes from the active tab on that connection, otherwise its latest recent root. On a GitHub connection, `owner/repo#number`, issue URLs, and selected repository names open directly; repository and issue text returns suggestions. Loading, empty results, and recoverable errors have explicit states. Load more fetches another page and may reorder results by relevance, while preserving the selected issue; Retry retains already loaded matches.

The open-issue picker shows up to twenty recent roots for the selected connection when its search field is empty. Recent roots, favorites, and tabs include cached summaries with full-title tooltips. Explicitly disconnecting a site removes its tabs, favorites, recent roots, closed tabs, navigation history, root views, and connection defaults. Temporarily unavailable connections retain their saved state.

Back and Forward restore the complete tab state at each root or tab navigation, reopening a destination if its tab was closed. Use the toolbar buttons, `Alt+Left` / `Alt+Right`, or `⌘[` / `⌘]` on macOS. Editing text does not trigger these navigation shortcuts. History is limited to one hundred entries in each direction and lasts for the current session; a new navigation clears the forward branch.

Reopen, Back, and Forward apply the saved filters and table presentation as that root's override. Later default changes leave the restored view intact. **Reset this root to default** adopts the connection's current default, including filters. Ordinary tab selection preserves default inheritance for uncustomized roots.

Drag the sidebar divider to resize it between 180 and 400 pixels (220 by default). When the divider is focused, arrow keys adjust it by ten pixels; Home and End select the limits. The width survives restarts.

Window size, position, and maximized state survive restarts. Saved bounds are clamped to an available monitor's work area when display arrangements change. Fullscreen state is not restored.

Workspace saves replace the previous file atomically. On Windows, temporary file-lock errors retry with bounded backoff; persistent failures remain visible and leave the previous saved file intact.

## Bulk triage

Select several visible rows in one issue tree with Command-click on macOS or Control-click elsewhere. Shift-click selects a visible range; Shift-Up and Shift-Down extend the range from the focused row. A plain click or arrow key returns to ordinary single-issue navigation. Bulk selection stays in the active tab and is cleared explicitly or by single-issue navigation.

The bulk bar can copy selected issue keys and summaries as separate lines, assign a person, change Jira priority, or transition status. Search for an assignee from the first selected issue; Canopy checks that person's eligibility for every selected issue. Jira transition choices are shared destination statuses, while each issue uses its own workflow transition. Choices requiring extra fields are unavailable. GitHub supports assignment and Open/Closed state, but not Jira priority.

Select an action and value, then use **Preview changes**. The preview lists every selected issue and explains unavailable fields. If only some issues are eligible, **Apply to eligible issues** explicitly limits the write to those issues. Each issue's options are checked again before writing. Results stay available in that tab after selection clears or you visit another tab, until you choose **Dismiss results**. Dismiss the report before previewing another bulk change. Failures have Retry, and a saved issue has Undo when its prior value can safely be restored. Undo checks the current provider state and may fail if another edit or workflow change intervened.

## Issue relationships

In an issue preview, **Inspect relationships** loads blockers, blocked issues, related links, and immediate parent/child paths. Each reference shows its direction, source issue, provider connection, and known completion state. **Preview** inspects the target in place. **Show in tree** selects and focuses a visible row in an existing owning tree on the same connection, expanding its ancestry and revealing it through filters and Hide done. A target outside loaded trees opens as a selected root. Parent and child references can be followed one hop at a time.

GitHub dependencies use the read-only REST dependency endpoints, hierarchy uses sub-issues and GraphQL `Issue.parent`, and related issues use GraphQL `Issue.relatesTo`. Jira uses inward/outward issue links, the parent field, and `parent` JQL search. Labels and textual mentions do not establish relationships. List reads stop after two pages per group; limits, incomplete responses, and permission failures remain explicit. GraphQL errors do not establish an empty related or parent group. Requests are cancelled when navigating away or reloading the window; late responses cannot populate another issue’s context. A manual tree refresh invalidates that tree’s inspected source results and pending inspections. Scheduled, focus, and reconnect refreshes preserve inspections when confirmed relationship-relevant tree data is unchanged. Changes or removals of sources or known targets invalidate affected results on the same connection. A response whose newly discovered target changed while loading stays unknown and offers reinspection. Unrelated roots, other accounts, and optimistic edits preserve inspected results.

Inspected relationships are a snapshot from the last inspection. Tree polling does not fetch provider relationship groups, so unchanged tree data does not prove that dependencies or outside-tree target statuses are unchanged. Use **Inspect relationships** or **Inspect blockers** again to refresh that snapshot. Incomplete and unavailable results remain explicit; missing fresh blocker status cannot be filled from older completed tree data.

The graph contains only relationships visible to the connection. Providers may omit inaccessible issues even when pagination finishes; empty visible results do not prove that a private graph is globally complete. GitHub cross-repository targets are identified explicitly. Targets outside the connection’s repository selection remain references and require adding the repository before inspection. Jira references whose target status is absent retain unknown status and unverified access. Missing Jira parent data stays unknown.

Work briefs include inspected relationship groups from the current connection and issue, including direction, repository boundaries, unknown target status, and partial/unavailable groups. An uninspected GitHub preview exports an explicit uninspected dependency state. **Retry** in the work-brief dialog fetches relationships read-only; closing the dialog cancels that request and discards late responses. Fresh inspected blocker statuses are authoritative, including unknown statuses; older tree data cannot fill missing fresh statuses. A visible inspected parent seeds the known ancestor path; unavailable parent groups stay unknown and visible empty groups stay empty. A fresh Jira preview also determines the immediate parent: unavailable identity stays unknown, explicit absence stays absent, and a usable parent can retain known ancestors from the tree. Without a fresh preview or inspected parent group, the brief can use the snapshot parent path.
